# 维护与发布

## 工作副本

不要在坚果云重解析目录中直接初始化 Git。使用本地普通目录作为工作副本，并设置两个远程：

```text
origin   https://github.com/xsnowfoxcode/QuickSwitch.git
upstream https://github.com/JoyHak/QuickSwitch.git
```

每次同步上游前，先查看 `git diff upstream/main`，确认本地路径处理、日志、中文界面等改动不会被覆盖。

## 构建依赖

- AutoHotkey v1.1.37.02 Unicode：运行 QuickSwitch 主脚本和编译应用。
- Ahk2Exe：将 `QuickSwitch-1.9.1.ahk` 编译为 EXE。
- AutoHotkey v2：运行 `Utilities/Build.ahk` 构建工具。
- 7-Zip：生成发布压缩包。

编译器不提交到仓库；请使用本机安装的工具或单独的受许可工具目录。

## 路径回归验证

`tests/Test-ValidateDirectory.ahk` 会直接调用当前源码中的 `ValidateDirectory()`，覆盖 UNC、带结尾分隔符的 UNC、盘符路径、相对目录和正斜杠输入。传入一个本机可访问的 UNC 目录运行：

```powershell
AutoHotkeyU64.exe tests\Test-ValidateDirectory.ahk "\\server\share" "$env:TEMP\QuickSwitch-ValidateDirectory.log"
Get-Content "$env:TEMP\QuickSwitch-ValidateDirectory.log"
```

所有用例都应输出 `PASS`，并且 UNC 用例的结果必须仍以两个反斜杠开头。

## 发布前检查

1. 确认版本文件名、EXE 文件版本和 Git 标签一致。
2. 测试 `\\server\share`、带结尾分隔符的 UNC、`C:\...`、相对目录和正斜杠输入。
3. 在真实 Windows 打开/保存对话框中验证 AutoSwitch 和菜单跳转。
4. 检查 `Errors.log`，不要把日志、`QuickSwitch.ini`、旧 EXE 或编译器缓存加入 Git。
5. 执行 `git diff --check`，检查许可证和敏感信息。
6. 生成 x64/x86 压缩包，并保存 SHA-256 值。

## GitHub 发布流程

```powershell
git fetch upstream
git switch -c agent/unc-path-fix
git status --short
git add .
git commit -m "Fix UNC path handling and document fork release"
git push -u origin agent/unc-path-fix
```

先在 Fork 中建立 Draft PR，验证通过后合并到 `main`，再更新现有 `v1.9.1` Release 的提交和 x64/x86 压缩包及 SHA-256 校验值。不要推送到 `JoyHak/QuickSwitch`，也不要声称使用上游代码签名证书。
